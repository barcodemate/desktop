BarcodeMate 0.5.4 is a correctness release: nothing new to learn, four things that were quietly wrong.

- **An imported column of same-length digits now names the format that fits it.** Thirteen digits is an EAN-13, and the app used to render them as Code 128 without comment, so the code scanned back as the right number under the wrong symbology. A line in the import dialog offers the match, with a button to switch. It stays an offer: printing digits as Code 128 is a real thing to want, so the import is never blocked, and nothing is said when a Format ID column names a format for each row.
- **Twenty messages are translated.** The first-run question about usage counting, the record of what this app has sent, and the privacy paragraph under About had no translations at all and appeared in English in the other twenty-three languages, including the screen that asks permission to count anything. A test now compares the shipped dictionaries against the messages the code asks for, so a missing translation fails the build instead of reaching you as English.
- **Three text fields tell a screen reader their own name.** Barcode data, encoder options and the import field were named by the label around them, which meant the name read out was that label plus everything typed into the field.
- **Backing out of a save or print dialog is no longer counted as a failure.** It was reported as app_fail, which made every cancellation look like a defect, while a step that genuinely threw was counted nowhere. The two are now app_cancel and app_fail, and only the step name travels, never the error text, which can hold a file name.

Usage counting remains off until you turn it on under About, and still contains no barcode content, file paths or identifiers.
