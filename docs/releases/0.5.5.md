BarcodeMate 0.5.5 fixes one defect, reported by two people on the same day.

- **Large batches print and export to PDF again.** A print-ready PDF of more than about 137 labels on an A4 sheet failed with `ERR_INVALID_URL (-300)`, and so did sending the same batch to a printer. The whole print document was handed to the print window inside a `data:` address, and Chromium refuses addresses longer than about 2 MB. The document is now served to that window by the app itself, held in memory for the one request and never written to disk. A 600-label, 29-page export is part of the test suite, so the limit cannot quietly return.

Thank you to the person who measured exactly where it broke (137 labels succeeded, 138 failed) and named the cause.

Usage counting remains off until you turn it on under About, and still contains no barcode content, file paths or identifiers.

Source commit: `SOURCE_COMMIT`. Validated Windows/macOS packages: https://github.com/barcodemate/desktop/actions/runs/SOURCE_RUN

Installers remain unsigned and macOS packages are not notarized.
